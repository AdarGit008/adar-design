# Commodore 64 / PETSCII — reference

Commodore 64 home computer: a chunky 40x25 PETSCII screen of light-blue bitmap type on deep blue, wrapped in the bright blue border frame, with a locked 16-color hardware palette.

**When to use:** When the user asks for Commodore 64, C64, PETSCII, breadbin-era home computer, BASIC/LOAD"*",8,1 screen, or a chunky blue 320x200 8-bit aesthetic.

**Signature element:** The bright blue border frame (#3f3fff with a #2f2fff inner edge) wrapping a 40x25 PETSCII screen of #a0a0ff bitmap type on #0000aa, closed out by a reverse-video status strip and a blinking block cursor

## Work-style rules

- The border frame is a load-bearing layout element, not decoration: wrap every screen in 24px–40px of bright blue #3f3fff with a 4px #2f2fff inner edge, then the #0000aa text field — a bare screen bleeding to the viewport edge is not C64.
- Quantize to the 8x8 hardware cell: an 8px sub-step and 16px line-height, with spacing tokens 8/16/24/32/40px, so all type and blocks land on the 40-column by 25-row character grid.
- Two-attribute color model: every component owns a foreground and a background attribute, and selection, hover, focus, and active states are always that pair inverted — never a tint, overlay, alpha wash, or a third highlight color.
- Stay inside the 16-color Pepto palette (paletteVariants.c64Pepto); the chrome itself lives in the blue/light-blue ramp (#0000aa, #2e2c9b, #3f3fff, #a0a0ff, #c6c6ff), and red/yellow/green are only used as attribute signals, never as surface fills.
- Type is bitmap: C64 Pro Mono at 16px or an integer multiple (16/32/48px), image-rendering: pixelated, no faux bold, no italic, no letter-spacing beyond 0.05em — the 8x8 cell must not shift.
- Motion is discrete: block cursor blink at steps(2, jump-none) 1s, character-by-character print, border color cycling through palette entries at 300ms steps — no easing curves and no tweened opacity.
- De-emphasize with the dim attribute (#6a6ab8) and with case, never with opacity or a gray filter — alpha produces colors outside the 16-entry set.
- Every screen carries PETSCII chrome: a top line of the product name plus a rule, a bottom status/prompt line ending in a blinking block cursor, and reverse-video framing on any raised panel.

## Component recipes

- **panel:** background: #0000aa; border: 4px solid #a0a0ff; border-radius: 0; padding: 16px 24px; color: #a0a0ff; font: 16px/16px 'C64 Pro Mono'; box-shadow: 0 0 0 4px #2f2fff, 8px 8px 0 #000066; — the title is a reverse-video run on the top edge: display:inline-block; background: #a0a0ff; color: #0000aa; padding: 0 8px; text-transform: uppercase; margin-top: -24px; and the panel sits inside the #3f3fff border frame, never flush to the viewport.
- **button:** font: 16px/16px 'C64 Pro Mono'; text-transform: uppercase; background: #a0a0ff; color: #0000aa; border: 4px solid #2f2fff; border-radius: 0; padding: 8px 16px; box-shadow: 4px 4px 0 #000066, 0 0 0 4px #0000aa; letter-spacing: 0.04em; transition: none; :hover { background: #c6c6ff; } :active { transform: translate(4px, 4px); box-shadow: 0 0 0 #000066, 0 0 0 4px #0000aa; } :focus-visible { outline: 4px solid #c6c6ff; outline-offset: 4px; } — secondary variant is the inverse pair: background: #0000aa; color: #a0a0ff; border-color: #a0a0ff.
- **input:** The field is a PETSCII cell run, not a modern box: background: #0000aa; color: #c6c6ff; font: 16px/16px 'C64 Pro Mono'; border: 4px solid #3f3fff; border-radius: 0; padding: 8px 16px; caret-color: transparent; box-shadow: inset 0 0 0 4px #2e2c9b; :placeholder { color: #6a6ab8; text-transform: uppercase; } :focus { border-color: #a0a0ff; outline: 4px solid #c6c6ff; outline-offset: 2px; } — draw the caret yourself as a one-cell 8x16 block in #c6c6ff animated steps(2, jump-none) 1s infinite; an invalid value keeps #c46c71 text and appends the literal ' ?SYNTAX ERROR' on the next line rather than recoloring the border alone.
- **statusbar:** A 24px footer strip in full reverse video: height: 24px; display: flex; align-items: center; gap: 24px; padding: 0 8px; background: #a0a0ff; color: #0000aa; border-top: 4px solid #2f2fff; border-radius: 0; font: 16px/16px 'C64 Pro Mono'; text-transform: uppercase; segments are 'READY.' then the memory readout ('38911 BASIC BYTES FREE') then the drive line ('DEVICE 8: OK'); the trailing cursor is an 8px wide #0000aa block on the light strip with steps(2, jump-none) 1s infinite.
- **menu:** Vertical PETSCII list, no bullets, no radius: item { display: block; font: 16px/16px 'C64 Pro Mono'; text-transform: uppercase; padding: 4px 16px 4px 32px; color: #a0a0ff; } the selected row is inverse video — background: #a0a0ff; color: #0000aa — with a '>' marker in the left gutter blinking steps(2, jump-none) 1s infinite, hover only brightens the text to #c6c6ff, and group breaks are a full-width run of '=' or a 4px #3f3fff rule, never a 1px hairline.

## Copywriting

- Voice: BASIC-prompt machine voice: clipped, literal, uppercase, and slightly stubborn. It reports the device, the drive, and the byte count, then waits at READY. — no greeting, no apology, no marketing adjective, and no second-person chit-chat.
- Case: headers=UPPERCASE, commands=UPPERCASE BASIC keywords (LOAD, RUN, LIST, SAVE), body=sentence case light-blue body copy; UPPERCASE for PETSCII labels, buttons, and status lines
- Prefixes: READY. SEARCHING LOADING RUN ?SYNTAX ERROR ?OUT OF MEMORY PRESS PLAY ON TAPE
- Verb table: start→RUN; stop→STOP; save→SAVE; load→LOAD; delete→SCRATCH
- Avoid: corporate filler ('seamless', 'leverage', 'empower', 'solution'), greetings, apologies, and 'Oops', emoji and modern flat iconography, mixed-case labels on buttons or in the status strip, exclamation stacks (!!!, ???) and exclamation marks in system copy, Press Start 2P, Chakra Petch, or any non-C64 display face

## Do

- Wrap the screen in the bright blue border frame (#3f3fff with a 4px #2f2fff inner edge) and keep 24–40px of it visible on every viewport — the frame is what makes a blue page read as a Commodore, not a DOS screen.
- Build on the 8x8 cell: 16px line-height, 8/16/24/32/40px spacing, and 8px-wide cursor blocks so type, rules, and images share one grid.
- Invert the attribute pair for selection, hover, focus, and pressed states (#a0a0ff on #0000aa becomes #0000aa on #a0a0ff) instead of reaching for a tint or a lighter blue.
- Keep chrome on screen: product-name header with a '=' rule, a bottom status strip printed in reverse video, and a blinking block cursor as the only animation.
- Set display and body type in C64 Pro Mono at 16px or integer multiples, uppercase for headings, with image-rendering: pixelated on all pixel art and integer 2x/3x scaling.
- Use the palette's attribute colors as signals — #c46c71 for errors, #edf171 for warnings, #a9ff9f for success — always accompanied by the literal word (ERROR, WARNING, OK).

## Don't

- Don't ship the screen without its border frame, and don't run the text field edge-to-edge as a full-bleed background — that reads as DOS/VGA, not C64.
- Don't add border-radius, soft/beveled shadows, glassmorphism, or gradient surfaces; depth is at most an 8px 8px 0 #000066 hard offset or a reversed panel.
- Don't de-emphasize with opacity, rgba(), or filter: grayscale — use the dim attribute #6a6ab8 or the palette's grey entries.
- Don't animate with ease-in-out, cubic-bezier, or tweened colors; the hardware could only step, so cursor blinks and border cycles use steps() at 0/100/300/1200ms.
- Don't use fractional font sizes (13px, 1.2rem) or fractional scaling on pixel art — the 8x8 cell and bitmap glyphs break.
- Don't introduce colors outside the 16-entry Pepto palette, and don't put red/yellow/green on large surfaces — they are attribute signals, not backgrounds.

## Accessibility

- The tested body pairing is #a0a0ff on #0000aa (about 5.7:1) and #c6c6ff on #0000aa (about 8.2:1); watch the tighter #a0a0ff on #2e2c9b panel (~4.6:1) and keep long text on the darker ground.
- Never let color alone carry state: the C64 palette's #c46c71 and #3f3fff sit near or below 4.5:1 against blue, so pair them with literal words (ERROR, WARNING, OK, READY.) and use them for large bold type, borders, or non-text signal.
- Keep all UI text at 16px or larger with 16px line-height, and let the C64 Pro Mono bitmap stack supply glyphs so PETSCII frames and block characters align; give every glyph-only control an accessible name (the '>' marker, the block cursor, the drive icon).
- Respect prefers-reduced-motion: stop the cursor blink and any border color cycling, print text instantly, and render the pressed-state shadow collapse as an instant change — every screen must stay readable with all steps() animation removed.
